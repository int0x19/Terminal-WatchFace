# Публикация Terminal Face на GitHub

Репозиторий содержит оба приложения и локально сохранённые релизы. Подготовка
не создаёт удалённый репозиторий и ничего не отправляет на GitHub автоматически.

## Текущее размещение

Подготовленная версия опубликована в [int0x19/Terminal-WatchFace](https://github.com/int0x19/Terminal-WatchFace),
ветка `main`. Исторические версии и эскизы доступны по тегам. Локальный
`origin` уже настроен; повторно выполнять `git remote add` не нужно.
Для дальнейшей отправки проверенных изменений текущей рабочей ветки:

```sh
git push origin HEAD:main
```

## Перед первой отправкой

1. Выполнить `sh tools/check.sh` и `python3 tools/check_publication.py`.
2. Просмотреть изменения, историю, пользовательские скриншоты и `docs/reference.jpg`.
   Проверка шаблонов токенов не доказывает отсутствие любых секретов или частных
   данных. История содержит обычные имя и email автора коммитов.
3. Собственный код распространяется под MIT; права на DejaVu и пользовательские
   референсы регулируются отдельно, см. `NOTICE`. Не включать чужие материалы,
   если нет необходимых прав на публикацию.
4. Убедиться, что ключи, пароли, токены, `.env`, `local.properties`, `signing.properties`
   и приватные сертификаты не отслеживаются. Если секрет когда-либо был закоммичен,
   одного удаления файла недостаточно: сначала отозвать секрет и проверить историю.

Архивные APK содержат открытый сертификат подписи, не приватный ключ.
Все прежние версии намеренно сохранены в `versions/` по запросу владельца.

## Первая отправка в новый пустой репозиторий

Создать пустой репозиторий в своём аккаунте GitHub и подставить его URL:

```sh
git remote add origin 'URL_НОВОГО_ПУСТОГО_РЕПОЗИТОРИЯ'
git push -u origin HEAD:main
git push origin --tags
```

Команды предназначены для нового пустого репозитория. Не использовать force push
или `--mirror`. Если `origin` уже настроен или удалённая `main` содержит историю,
сначала проверить её и согласовать объединение.

Локальная ветка `main` пока хранит первоначальный шаблон 931c71e. Подготовленные
две сборки находятся в `feat/dual-watchfaces`; `HEAD:main` публикует именно текущее
состояние этой ветки в удалённую `main`, не переписывая локальную историю.
В GitHub выбрать опубликованную ветку основной и проверить первый запуск Actions.

## Что собирает GitHub Actions

Workflow `.github/workflows/build.yml` запускается на push, pull request или вручную.
Он собирает Compact/Large, проверяет WFF 2, APK/AAB, подписи, лицензии шрифтов,
отсутствие DEX, lint, память и сохранённые эскизы. APK и неподписанные release AAB
доступны в артефакте `terminal-face-compact-and-large` 14 дней.

Все actions закреплены на полные SHA коммитов; Gradle и Google JAR проверяются
по SHA-256. Workflow имеет только `contents: read`, не использует секреты,
`pull_request_target`, push, автоматическое создание Releases или загрузку в Play.
Состояние запусков доступно на [странице Actions](https://github.com/int0x19/Terminal-WatchFace/actions).
Android SDK устанавливается явно: наличие sdkmanager в образе runner не предполагается.

## Подпись приложений

Локальные APK подписаны текущим ключом разработки. CI без настроенного постоянного
ключа создаёт свой временный debug-ключ. Поэтому CI-APK не предназначен для
надёжного обновления поверх APK, подписанного другим ключом, даже с тем же ID.
Не удалять настроенный циферблат ради такого обновления без резервирования настроек.

Для регулярных публичных релизов настроить отдельный постоянный release-ключ,
резервную копию вне репозитория и ограниченные GitHub Secrets/Environments.
Не коммитить ни ключ, ни пароли. Production-подпись и публикация в Google Play
не входят в эту подготовку; release AAB сейчас не подписаны.

## Идентификаторы и старые установки

Compact использует `dev.int0x19.watchface.terminal.compact`, Large —
`dev.int0x19.watchface.terminal.large`. Оба отличаются от прежнего
`dev.int0x19.watchface.terminal`, поэтому не заменяют его и могут быть
установлены одновременно. Поставщиков дополнений и оформление выбирают отдельно
для каждого приложения; автоматического переноса старых настроек нет.

Имена пакетов после начала распространения лучше сохранять. Для новых выпусков
увеличивать versionCode в `watchface/variants.properties` и версию соответствующего
варианта; архивировать только после полной проверки. Новые пакеты имеют code=14,
версии `0.8.1-compact` / `0.9.1-large`; номера оформления 0.8.1 / 0.9.1 не менялись.
